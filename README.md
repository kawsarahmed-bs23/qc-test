# QuarryConnect E2E

Browser tests for **QuarryConnect Admin** (`admin.*`) and its sign-in through **Identity** (`id.*`). They use a real Chromium browser. Since QC-742 Admin is the Angular app `quarryconnect-admin-ui` (`ADMIN_URL`, hash routes such as `#/users`) on top of the API-only `QuarryConnect.Admin.WebApi` (`ADMIN_API_URL`); the `setup` project signs in through the app's PKCE flow on Identity's page and saves the session, tokens included (they live in the app's `localStorage`), to `.auth/<env>/admin.json`. The project lives at the workspace root on purpose: it tests the deployed sites from the outside and belongs to no single app repo.

- Playwright + TypeScript, page objects in `pages/`, specs in `tests/`.
- One codebase, three environments: `local`, `dev`, `prod`.
- Every run writes a dated report to `reports/<env>/<timestamp>/`:
  - an HTML report;
  - JUnit and JSON results;
  - screenshots, videos and traces for failures.

## Setup

```powershell
cd quarryconnect-e2e
npm install
npm run install:browsers
```

Add the test accounts for an environment. Copy `env/example.secrets.env` to `env/<env>.secrets.env`; the file is git-ignored. You need:

| Variable | Needed | Notes |
| --- | --- | --- |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | yes | A dedicated Identity test account. Never a real person's account. Since QC-775 Admin needs a HOST_MASTER platform admin (`app.PlatformAdmins`) who signed in with two-step verification, so locally the run does not sign in as this account: `fixtures/globalSetup.ts` seeds the throwaway platform admin `e2e.qc775.admin@quarryconnect.test` (this account's password hash copied, two-step verification on with an authenticator key made for the run and kept only in the git-ignored `.auth/<env>/platform-admin.json`) and `auth.setup.ts` signs in with it, typing the TOTP code; `fixtures/globalTeardown.ts` removes it. Elsewhere this account must already be a platform admin with two-step verification. |
| `DRIVER_EMAIL` / `DRIVER_PASSWORD` | optional | Any non-admin user. Without it the permission-denied test is skipped. |
| `APP_ADMIN_AUTHENTICATOR_KEY` | optional, in `env/<env>.app.secrets.env` | The base32 authenticator key of `APP_ADMIN_EMAIL`, for when Identity asks that account for two-step verification. `tests/app/app.setup.ts` types its TOTP code; without it the `app-setup` sign-in stops with a message naming this variable. |

In CI, set the same names as pipeline secrets instead of files.

## Run

```powershell
npm run test:local      # Admin app http://localhost:4400, Admin API https://localhost:7090, Identity :7050
npm run test:dev
npm run test:prod
npm run test:smoke      # only @smoke, uses TEST_ENV (default local)
npm run test:headed     # watch the browser
npm run report -- local # open the latest HTML report for an environment
```

Extra Playwright arguments pass through:

```powershell
npx cross-env TEST_ENV=dev ALLOW_WRITES=true playwright test tests/04-features.spec.ts
```

## Environments and safety

`env/<env>.env` holds the URLs, the host under test (`HOST_NAME`, as shown in the Admin host list) and the safety switches. Each test is tagged by what it is allowed to do.

| Tag | What it does | local | dev | prod |
| --- | --- | --- | --- | --- |
| *(none)*, `@smoke` | Reads only | ✅ | ✅ | ✅ |
| `@write` | Changes a value through the UI, verifies it, then **restores the original** in a `finally` block | ✅ | opt-in `ALLOW_WRITES=true` | **never** |
| `@create` | Adds a host to HOST_MASTER and Identity (Admin has no delete; locally `seed/master-e2e-hosts.remove.sql` and the matching `identity-qc7xx.remove.sql` delete the `e2e-qc7*` hosts afterwards, elsewhere rows stay) | opt-in `ALLOW_CREATE_HOSTS=true` | opt-in | **never** |
| `@restart` | Restarts the host API from the Environment page | opt-in `ALLOW_RESTART=true` | opt-in | **never** |

Production is hard-wired read-only in `config/environment.ts`, so no flag can turn writes on there. Write tests only ever touch a short allow-list of harmless settings:
- the Maps feature;
- the number prefix;
- the primary colour;
- `DispatchSnapshot:RateLimitPermitsPerHour` and a few driver-location intervals.

They never touch keys such as `HostOrganisationId`, JWT or CORS. Tests run one at a time (one worker) because they share one host.

Locally, `fixtures/globalSetup.ts` notes the last `app.ChangeLogs` row in HOST_MASTER before a run and `fixtures/globalTeardown.ts` deletes the rows the test admin (the throwaway platform admin, or `ADMIN_EMAIL` where none is seeded) added during it, so the activity log does not fill up with test changes.

Since QC-775 Identity reads hosts (client id, allowed addresses, branding, two-step requirement, active flag) from the Admin API's `GET api/identity/hosts` and caches them for 5 minutes (`HostMaster:CacheDuration`). Cases that change a host in HOST_MASTER and then check Identity (HMI-03…07, HM-05) poll for up to `IDENTITY_HOST_CACHE_SECONDS` (330 in `env/local.env`). To run them quickly, start Identity with a short cache and lower the wait to match:

```powershell
$env:HostMaster__CacheDuration = '00:00:05'; dotnet run --project quarryconnect-identity/QuarryConnect.Identity --launch-profile https
npx cross-env IDENTITY_HOST_CACHE_SECONDS=20 playwright test tests/19-host-master-identity.spec.ts
```

Every QC-775 throwaway account is `e2e.qc775.*@quarryconnect.test` (`seed/identity-qc775-user.apply.sql`, removed by `seed/identity-qc775-users.remove.sql`), and the throwaway host is `e2e-qc775` (`seed/master-qc775-host.apply.sql` / `.remove.sql`); none of the shared accounts or the target host is changed by them.

## Adding tests

In Claude Code, run `/e2e-test <feature or ids>` from the workspace root. The project skill in `.claude/skills/e2e-test` writes the cases in this project's style, runs them and reports. Or follow the rules below by hand.

- Put selectors in `pages/`. Prefer the element ids the Admin site exposes (`#features-save`, `#tab-environment`, `data-*` hooks) over CSS that might change.
- Use the `targetHost` fixture (`fixtures/test.ts`) for the host's UUID. It is looked up by `HOST_NAME`, never hard-coded.
- Anything that changes data gets the `@write` tag and restores the original value in `finally`.
